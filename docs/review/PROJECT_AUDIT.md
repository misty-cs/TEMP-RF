# Project audit — 2026-09-27

Verdict: the current implementation is not ready to support a clean, fully tuned fairness comparison. Several concrete defects precede any interpretation of results. These findings concern methodological bias and implementation consistency, not intent.

Scope: inspected the active orchestration, dataset configuration/loaders, training and replay, trajectory selection, common evaluation, baseline implementation, audit, aggregation and methodological documentation; inspected legacy entry points selectively. Parsed all 32 top-level Python files successfully. Ran small reproductions using extracted functions rather than launching training. No completed common evaluations or selected tuning files exist in this workspace. WiSig and Pycom links resolve; NEU does not. No full training, dataset-wide duplicate scan or performance ranking was run. Historical files under `_unused` are not certified.

## Confirmed defects, ordered by importance

1. **P1 — Phase-1 tuning cannot finish selection.** `tune_phase1.py:44` serializes only keys containing `acc`, dropping `val_sel`, but line 78 unconditionally reads `val_sel`. `run_phase1` actually returns that metric (`phase1_initial_training.py:594`). Reproduced the exact dictionary comprehension: it retains val_acc/test_acc and drops val_sel. Fix serialization and invalidate or reconstruct incomplete tuning caches before expensive runs.

2. **P1 — The primary tuned protocol changes the methods being compared.** `common_eval.py:458` uses D.argmin/D.min for every rule. For k-NN this replaces global k-neighbor voting and mean neighbor distance with nearest class-wise mean k-distance; predictions as well as scores can differ. For OpenMax it replaces unknown-class probability with 1 minus maximum known-class probability. Thus top-level closed/AUROC and nested tuned operating metrics can come from different classifiers/scores, yet aggregation presents them together. Preserve each rule's original prediction and unknown score for every threshold protocol; obtain pseudo-unknown scores by applying the corresponding held-out-class model.

3. **P1 — “Leave-one-device-out” calibration is not equivalent across methods.** `common_eval.py:461` merely masks the true class column in an already fitted probability matrix. MSP/probe retain the omitted class in the softmax denominator; the probe is not refit, and OpenMax is not recalibrated. Its hyperparameter selection does refit/remove classes, so calibration uses a different surrogate. This preferentially changes the problem for probability-based rules relative to independent distance-based rules. Refit the applicable classifier/calibrator and renormalize applicable head probabilities after class removal, while explicitly acknowledging that the shared backbone has still seen those devices.

4. **P1 — Replay consumes the allegedly held-out prototype groups.** `phase2_sequential_finetuning.py:149` loads the entire previous session with labels for replay; lines 302–303 retain the entire current session for the next replay step. `finetune.py:540–551,603–607` uses these labelled source embeddings to form centroids in the training loss. Phase 3 excludes only the direct training groups (`phase3_trajectory_building.py:238–250`), so some retained validation/test groups already influenced training through replay. This also gives sequential training more labelled source data than the joint control. Restrict replay to actual training samples, or explicitly account for all replay-used groups and labels in provenance and budgets.

5. **P1 — Failed or unaudited results remain eligible for publication tables.** `main.py:88` skips whenever common_eval.json exists, even if an audit failed or never ran. `aggregate.py:25–28` loads every such JSON without checking audit.json, AUDIT_FAILED, manifests or expected split/seed completeness. Interrupted, stale and failed runs can be silently included. Require a passing, matching audit before treating a run as complete or aggregating it; report missing runs.

6. **P2 — Statistical implementation does not match the declared primary analysis.** FAIRNESS.md declares tuned known_ok and unk_det among primary outcomes, but `aggregate.py:117` tests only closed and AUROC. Only t-test p-values receive Holm correction; Wilcoxon p-values do not. Corrections are per dataset, not an explicitly combined family across both datasets. Define the family precisely and implement every declared outcome/test. Split averaging is a good improvement, but overlapping enrolled devices and the same recordings across splits still limit independence; five seeds do not create new capture sessions.

7. **P2 — OpenMax's prior default is excluded from its tuning grid.** `common_eval.py:210` searches alpha {1,2,5,K}, whereas its default/tie preference is min(10,K). With K=12 or 16, alpha=10 is never a candidate, so the promised default-preserving tie rule cannot retain it. Include the declared default in the grid or change and document the default prospectively.

8. **P2 — fixed90 does not calibrate on all of Part C.** `common_eval.py:83–90,343–347` removes the hardest 25% per device according to static-centroid distance, then computes the 90th percentile on the remaining 75%. This contradicts FAIRNESS.md's description of accepting 90% of Part C, and defines the calibration subset using one of the competing methods. On continuous static scores this roughly targets the 67.5th percentile of the full distribution, not its 90th. Use all C for fixed90; describe the objective protocol's static-defined stress subset separately.

9. **P2 — The automated audit is weaker than its claims.** `audit_run.py:46` accepts two split arrays instead of requiring all three; lines 77–80 infer bank exclusion from counts in log text rather than actual saved sample/group provenance; lines 84–87 only require positive known/unknown totals and configuration device lists, without verifying expected per-device counts or recomputing the test hash. Phase-3 checks compare labels and reconstructed groups, not the saved sample identities. Missing training-group files also cause Phase 3 to use all samples instead of stopping. Persist and check actual identities; fail closed for missing required provenance.

10. **P2 — Tuning caches and resumed runs lack configuration identity.** Phase-1 cache keys omit epochs/code/data/preprocessing; Phase-2 keys omit seed and the selected Phase-1 checkpoint. `main.py` trusts PHASE3_DONE and existing outputs without matching their settings to current selections. The same tuning directory is also reused for CFO variants. Changing seed, preprocessing, source checkpoint or code can silently reuse incomparable settings/results. Key caches and checkpoints by relevant manifests, and reject incomplete candidate/seed grids rather than selecting from available successes only.

11. **P2 — The reference split is transductive at the representation level.** `phase3_trajectory_building.py:203–213` adapts BN on the full reference session before splitting A/B/C. Consequently B and C affect the embedding model; they are group-disjoint for prototypes but not entirely held out from fitting. All rules share this, so it is not by itself evidence of a TEMP-RFF-only advantage. Either adapt on A alone for strict isolation, or describe and separately evaluate this shared transductive reference adaptation.

12. **P2 — Dataset selection uses the eventual test sessions.** WiSig pool ranking (`data_utils.py:196–239`) considers signal counts and inferred burst diversity across all four dates, including the test date. Pycom's eligibility rule (`pool_check.py`) includes Day 5. This is availability/quality-conditioned cohort selection, not test-label-driven model tuning, but the blanket claim that test sessions/unknown devices are used only for final scoring is too strong. State the selection rule and exclusions, and limit claims to the eligible cohort; preferably freeze eligibility using pre-test data for a prospective evaluation.

## Uneven tuning and study-design limitations

- TEMP-RFF has 54 bank/window/decay candidates on WiSig and 72 on Pycom, plus alpha selection; k-NN-window has 24/32, OpenMax currently 24, probe 4. Unequal grids are disclosed and are not automatically unfair, but do not establish comparable tuning adequacy. Report validation curves, selected boundary frequencies and computational budgets. Actual under-tuning cannot be determined without results.
- `temp_rff_p1` and `temp_rff_nowt` inherit the full method's chosen window/decay (and bank size where applicable), rather than selecting their own best settings. Appropriate as fixed-setting component ablations; insufficient as independently optimized competitors.
- Few-shot uses equal new target support but unequal historical reference data (`common_eval.py:509`): TEMP-RFF retains its earlier sessions, static/k-NN start from A. Add equal-history few-shot controls before attributing a difference solely to the method.
- Phase-1/2 hyperparameters are selected with a centroid-based validation proxy, shared across downstream rules. This is a legitimate shared-backbone comparison but does not establish superiority over independently trained and tuned methods, especially classifier-head baselines. Label the claim accordingly.
- Part B is reused for method hyperparameters and threshold-protocol selection. This is validation reuse, not direct test leakage, but increases selection optimism as the grid expands.
- FAIRNESS.md discloses a tie-rule change after an old-model test diagnostic. Calling the resulting protocol completely untouched by test feedback would be inaccurate. Preserve that disclosure and freeze a versioned protocol before new confirmatory evaluation.
- Selection-weight sensitivity (`common_eval.py:498–500`) uses strict argmax and ignores the actual 0.001/default tie rule. Even weight 0.5 can therefore disagree with the real selected setting; this is not a clean weight-only sensitivity analysis.
- README_RUN.md and early METHODS_NOTES.md sections retain old split-0/global-tuning, accuracy-only, two-threshold and fixed-prototype descriptions alongside later contradictory updates. Consolidate one current protocol. The paper plot modules still accept legacy Phase-4 result objects, so do not assume they visualize the common-evaluation schema.
- Installed NumPy is 2.2.6 while requirements.txt pins 2.3.5; TensorFlow 2.20.0 and scikit-learn 1.8.0 are available. Record a reproducible environment. NEU requires restoring its broken data link before an end-to-end check.
